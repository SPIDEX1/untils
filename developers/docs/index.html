Quick start

  1. Make your game as a normal HTML5 game with an index.html.
  2. (Recommended) Download the SDK below and add it to your game.
  3. Put everything in one .zip file. index.html must be at the top level of the zip.
  4. Open your dashboard, press + ADD NEW GAME, fill in the details, add your icon and zip, and press UPLOAD GAME.
  5. Our team reviews it (up to 2 days). After approval we make it live on UNTILS.

Device: mobile or desktop

When you upload, choose Mobile game if it plays well on phones and PC. Choose Desktop game if it needs a keyboard or mouse. Desktop games show "This game is for desktop (PC) only" on phones instead of a Play button.

Recommended game size (what the player sees)

WhereWhat to do
PCDesign for 1280 x 720 (16:9 landscape). The game area is shown in a 16:9 frame and can go fullscreen.
PhoneWhen the player presses Play, the game opens fullscreen. Support portrait (720 x 1280) or landscape, and tell players if one is required.

Most important: make the game responsive. It must fill the window (window.innerWidth x window.innerHeight), keep its aspect ratio, and never need scrolling. Add this to your page:

<meta name="viewport" content="width=device-width,initial-scale=1,viewport-fit=cover">
<style>html,body{margin:0;height:100%;overflow:hidden;touch-action:manipulation}</style>

Game icon (logo) - required

ItemRule
ShapeSquare (width = height).
SizeMinimum 512 x 512 px. We recommend 1024 x 1024 px. Smaller or non-square icons are rejected by the upload form.
FormatPNG, JPG or WebP. Under 2 MB.

What to put in it:

  • One clear subject: your main character, object or logo mark, in the centre.
  • Keep about 10% empty space around the edges. UNTILS rounds the corners itself, so do not round them.
  • Bright, high-contrast colours and a solid background. It must look good very small (about 60 px).
  • Little or no text. Tiny text becomes unreadable. A short game name in large letters is fine.
  • No borders, no store badges, no "NEW" or "FREE" stickers, no blurry or stretched images.
  • Only artwork you made or are allowed to use. No copied characters or logos.

The icon is shown on the game card, the Play screen, "More games" and the popular banner.

Popular banner - optional

If the UNTILS team marks your game as Popular, it appears in the big banner at the top of the home page. A banner is optional, but without one your game shows only its icon on a gradient.

ItemRule
Size1920 x 400 px (ratio about 4.8 : 1). Minimum 1600 px wide.
FormatPNG, JPG or WebP. Under 2 MB.
Safe areaThe banner is cropped on small screens. Keep important art in the centre 1000 x 190 px.
TextDo not write the game name or a Play button on it. UNTILS adds the title and a Play Now button on the left, with a dark fade for readability. Keep the left side calm.

How to upload: choose it in the Popular banner field when you add the game. You can also add or change it later: open your dashboard, click the game, pick a new banner, and press SAVE CHANGES.

Screenshots - optional

ItemRule
CountUp to 5.
SizeMinimum 640 px wide. We recommend 1280 x 720 (landscape) or 720 x 1280 (portrait for phone games).
FormatPNG, JPG or WebP. Under 2 MB each.

What to show: real in-game screens (menu, gameplay, a level, a win or upgrade screen). No fake or edited-in screens, no device frames, no big promo text, no screens from other games.

Screenshots appear at the very bottom of your game page. Click one to see it large. You can remove or add screenshots later from the dashboard.

Review and going live

  1. PENDING - your game is waiting. Our team plays it on PC and phone and writes reviews. Review takes up to 2 days. While you wait, click your game in the dashboard and press Preview on UNTILS to play it on a UNTILS game page. The preview link works for 24 hours.
  2. APPROVED or REJECTED - the leader decides. If rejected, a note explains why on your dashboard, and you can fix it and upload again.
  3. LIVE - the game is public on UNTILS. A green PLAY button appears next to it in your dashboard, together with plays, players and likes. Messages from our team also show there, next to the game.
Updating a live game: click it in your dashboard to change the name, description, category, icon, banner, screenshots, or upload a new version. If you rename a game, its link changes too. Changes to the name, description, category, icon, banner and screenshots go live right away when you press SAVE CHANGES. A new version (new zip) of a live game is reviewed first: it shows as "New version in review" and the current version keeps running until we approve it (up to 2 days).

HTML SDK

HTML SDK (version 1.2.0) is one small file, untils.js, for HTML5 games. It gives your game progress saving, pause/resume, share links, language, fullscreen and event tracking. Ads and leaderboards are reserved and will work later without changing your code. It is optional, but recommended.

Import

  1. Download untils.js.
  2. Put it next to your index.html inside your game folder (and so inside the zip).
  3. Add this in your page before your own game script:
<script src="untils.js"></script>

Using a local copy means your game also runs on your own PC without UNTILS. In that case the SDK switches to offline mode: saves go to your browser and ads are skipped, so nothing crashes.

Full flow

async function main() {
  await Untils.init();               // 1. always first

  Untils.loadingStart();             // 2. assets start loading
  await loadAssets();
  Untils.loadingFinished();          // 3. menu is ready

  let level = await Untils.load("level", 1);   // 4. read saved progress

  playBtn.onclick = () => {
    Untils.gameplayStart();          // 5. player starts playing
  };

  function onGameOver() {
    Untils.gameplayStop();           // 6. player died / opened menu
    Untils.save("level", level);     // 7. save progress
    Untils.showAd("interstitial");   // 8. ad between levels (not live yet)
  }

  rewardBtn.onclick = async () => {
    const watched = await Untils.showAd("rewarded");   // 9. watch ad for a reward
    if (watched) giveCoins();
  };

  Untils.onPause(() => pauseGame());     // tab hidden / app switched
  Untils.onResume(() => resumeGame());
}
main();

Limits and tips: all saved values together can be about 900 KB per game. If you go over, save() returns false and prints a warning. Save small things (level, coins, settings), not big data. Today saves stay in the player's browser on that device. When player accounts arrive, the same save and load will work on every device, so your game needs no change.

Inspector view and SDK check

Every time you upload a game or a new version (new zip), UNTILS opens an Inspector view panel in your dashboard. It starts your game in the background and checks whether the Untils SDK is running. If the SDK is found, the panel just confirms it. If not, it tells you the SDK was not detected (the SDK is optional, so your game can still be reviewed).

The panel always has a link to the Inspector page. There your game opens like on UNTILS, with a console on the side that shows each event as it happens:

  • init: the SDK started (and which SDK and version).
  • loading start and finished, gameplay start and stop.
  • save: how many keys and how big, and track events with their data.
  • ad and score requests (ads and leaderboards are not live yet).
  • error: errors from your game, when the SDK is running.

Chips at the top turn green when an event has fired. You can switch between Desktop and Phone size, restart the game, and copy the log.

When does the panel appear? Only when you upload a zip (first upload or a new version). It does not appear when you only change the text, category, icon, banner or screenshots. You can open the Inspector at any time from your game's details in the dashboard. For a live game with a new version waiting for review, you can inspect the new version too.

Install and build

  1. Unzip the file into your Unity project folder (the one that contains Assets). Merge the Assets folder.
  2. In Unity open the menu Untils → Apply recommended WebGL settings. This sets everything in the table below for you.
  3. In your first script call Untils.Init(...) and use UntilsPrefs instead of PlayerPrefs (see the code below).
  4. File → Build Settings → WebGL → Build.
  5. Zip the contents of the build folder, so index.html is at the top of the zip, and upload it in your dashboard. UNTILS then opens the Inspector view to check your SDK.
Player Settings (WebGL)Value
Resolution and Presentation → WebGL TemplateUntils
Publishing Settings → Compression FormatGzip (Brotli or Disabled also work)
Publishing Settings → Decompression FallbackOn
Publishing Settings → Data CachingOff

The template makes your game fill the whole window (phones and PC), shows a loading bar, loads untils.js, starts the SDK, and tells UNTILS when loading starts and finishes. You do not need to call LoadingStart yourself.

Code

using UnityEngine;

public class GameManager : MonoBehaviour
{
    int level;

    void Start()
    {
        Untils.Init(ok =>
        {
            level = UntilsPrefs.GetInt("level", 1);    // saved progress
            StartGame();
        });
        Untils.OnPause  += () => Debug.Log("paused");   // optional
        Untils.OnResume += () => Debug.Log("resumed");
    }

    public void OnPlayPressed() { Untils.GameplayStart(); }

    public void OnGameOver()
    {
        Untils.GameplayStop();
        UntilsPrefs.SetInt("level", level);             // saved automatically
        Untils.CommercialBreak(() => ShowGameOverScreen());   // ads not live yet: continues at once
    }

    public void OnRewardButton()
    {
        Untils.RewardedBreak(rewarded => { if (rewarded) GiveCoins(); });
    }
}

If something goes wrong

  • "untils.js is not loaded" in the browser console: the WebGL template is not set to Untils. Run the menu Untils → Apply recommended WebGL settings and build again.
  • Progress is not saved: you used PlayerPrefs. Change it to UntilsPrefs. Unity's own save uses IndexedDB, which is blocked in the UNTILS sandbox.
  • The game stays on the loading bar: open the browser console (F12). Check that the zip has index.html at the top and the Build folder next to it.
  • Very large builds: keep the zip under 50 MB. Compress textures and audio.

This SDK is in beta. If you find a problem, please tell us through the contact page and include your Unity version.

Install and build

  1. Unzip the file into your Cocos project folder (the one that contains assets). Merge the folders. You get assets/UntilsSDK and build-templates/web-mobile/untils.js.
  2. In your first script call Untils.init() and use UntilsPrefs instead of the local storage (see the code below).
  3. Project → Build → Platform: Web Mobile → Build. Web Mobile works on phones and PC. Set the build Orientation to match the Mobile screen option you choose in the dashboard.
  4. Open the build folder and check that untils.js is next to index.html.
  5. Zip the contents of the build folder, so index.html is at the top of the zip, and upload it in your dashboard. UNTILS then opens the Inspector view to check your SDK.

You do not need to call loadingStart / loadingFinished: the SDK sends them for you (set Untils.autoLoading = false to do it yourself). When the tab is hidden the SDK also pauses the game and sound, and resumes them when the player returns (set Untils.autoPause = false to handle it yourself).

Code

Cocos Creator 3.x (TypeScript)

import { _decorator, Component } from 'cc';
import { Untils, UntilsPrefs } from './UntilsSDK/Untils';
const { ccclass } = _decorator;

@ccclass('GameManager')
export class GameManager extends Component {
    level = 1;

    start() {
        Untils.onPause(() => console.log('paused'));      // optional
        Untils.onResume(() => console.log('resumed'));

        Untils.init().then(() => {
            this.level = UntilsPrefs.getInt('level', 1);    // saved progress
            this.startGame();
        });
    }

    onPlayPressed() { Untils.gameplayStart(); }

    onGameOver() {
        Untils.gameplayStop();
        UntilsPrefs.setInt('level', this.level);            // saved automatically
        Untils.commercialBreak().then(() => this.showGameOverScreen());   // ads not live yet: continues at once
    }

    onRewardButton() {
        Untils.rewardedBreak().then((rewarded) => { if (rewarded) this.giveCoins(); });
    }
}

Unity, Cocos and other engines

Web (HTML5) exports from game engines work if the zip follows the same rules as above: index.html at the top, relative paths, under 50 MB.

Unity (WebGL)

  1. File → Build Settings → WebGL → Build.
  2. In Player Settings → Publishing Settings: Compression Format can be Brotli, Gzip or Disabled (UNTILS serves all three). We recommend Gzip with Decompression Fallback ON. Turn Data Caching OFF.
  3. Zip the contents of the build folder (index.html, Build/, TemplateData/) so index.html is at the top of the zip.
  4. Make the canvas fill the window so it works on phones and PC.
Using Unity? Use the Unity SDK. It adds the WebGL template and UntilsPrefs so progress is saved.

Cocos Creator (Web)

  1. Project → Build → Platform Web Mobile → Build.
  2. Zip the contents of the build folder, so index.html is at the top of the zip.
Using Cocos Creator? Use the Cocos SDK. It adds UntilsPrefs so progress is saved, and sends loading and pause events for you.

Godot

Export for Web and zip the export as above. For Godot 4, make sure Thread Support is off (threads need special server headers). A plugin for the UNTILS SDK is planned. We have not tested Godot in depth yet, so please test your game after upload and tell us if something fails.

Rules

  • Your game must be yours, or you must have the right to publish it.
  • No adult content, hate, or violence aimed at real people.
  • No malware, crypto-mining, tracking, or collecting players' personal data.
  • No misleading names, icons, screenshots or banners.
  • The game must work, load in a reasonable time, and not crash.

Questions? Use the contact page.
